# 공개/비공개 경계 (Boundary Slot)

## 책임

공개 트리에 *들어갈 수 있는* 자산과 *들어갈 수 없는* 자산을 분류한다.
agent가 *과민 반응하지 말아야 할 것*도 명시한다.

## 현재 상태

- B1 자산 분류 매트릭스 — 박제 완료 (확장 결정 포함).
- B2 격리 폴더 운영 규칙 — 박제 완료 (읽기/백업/지식이전 포함).
- B3 agent 과민 반응 금지 — 박제 완료 (추가 항목 포함).
- B4 판단 요청 절차 — 박제 완료 (기록 형식 명시 포함).
- 2026-09-07 재개 정합: 격리 열람·IPSW 언급을 이유로 전체 작업을 멈추던 문구를 AGENTS §0/§3/§4에 맞게 수정했다. 공개 XNU 헤더·ABI의 출처 분류와 외부 로컬 매체를 사용하는 런타임 검증 경계는 B7에 기록한다.
- Design D10의 Linux 커널/드라이버 backend 분류 질의를 B5(e)에서 회수했다. 구현·런타임 성공 판정은 Build Plan/Design에 남긴다.
- (F) 이전 통합 검증 — 당시 OPEN_QUESTION 7건 종결(RESOLVED 7).
  B6(공개 DeviceTree 허용 출처 목록) 신설. D5×BP3 단계 6/8×B1 대조:
  모순 없음 확인(B6 말미 박제).

## 원하는 상태

- 자산 분류 매트릭스가 박제된다.
- 격리 폴더 운영 규칙이 박제된다.
- agent 행동 지침 (과민 반응 금지)이 박제된다.
- 공개 코드/빌드 입력, 격리 분석 결과, 외부 로컬 실행 매체를 구분한다. 분류 검토는 EFI·VM·드라이버 구현과 병렬로 진행하며, 아직 판정하지 않은 자료의 공개 반입만 보류한다.

### B2. 격리 폴더 운영 규칙

> *결정 근거: AGENTS.md §5(격리 자산 보호 메커니즘)를 유지하면서, 운영 책임은
> *사용자*에게 있음을 명시한다. 코드 의존성은 0이고, *지식*만 이전된다.*

- 위치: 트리 최상위 `_isolated/`.
- `.gitignore`에 강제 제외 항목이 있다.
- `tools/git/hooks/pre-commit` 가드가 staged 영역을 검사한다.
- 설치: `bash tools/git/install-hooks.sh` (idempotent).
- 격리 폴더는 *참고용*이다. 공개 트리 코드는 격리 폴더의 자산을
  *import하지 않고, 빌드 시 참조하지 않고, include하지 않는다.*
- 격리 폴더에서 Nextcore로 *지식이 이전*되는 것은 허용된다 — 단,
  Design D8의 자연어 외부 인터페이스 요구로 한정한다. 코드·내부 구조체
  레이아웃·상수·오프셋·추출물은 옮기지 않는다. 이름만 바꾼 코드도 금지다.

#### B2-1. 읽기 권한 정책

- 메인테이너와 현재 작업 범위에서 분석을 위임받은 agent는 필요한 격리
  자료를 로컬에서 읽을 수 있다. AGENTS §0이 허용한 역공학·열람 자체는
  재확인 또는 전체 작업 중단 사유가 아니다.
- 격리 내용·원문·바이너리를 외부 contributor, PR, 공개 보고에 전달하지
  않는다. 공개 메타는 Inventory의 항목·출처 분류·상대 경로·판정 범위로
  한정하고, 내부 구조·키·원문을 포함하지 않는다.
- 미위임 자료의 접근·공개 반입이 필요한 경우 그 작업 범위를 특정해
  기록한다. 독립적인 코드 구현·공개 문서 조회·로컬 실행 검증은 계속한다.

#### B2-2. 백업 정책

- 격리 폴더는 *사용자 책임* 영역이다. Boundary는 보관/복구를 책임지지 않는다.
- Git, GitHub, 원격 백업, 클라우드 동기화에 *자동으로* 포함되지 않는다.
  `.gitignore` 강제 제외와 pre-commit 가드는 Git 추적·staging을 위한 보호이며,
  별도 백업·동기화 프로그램까지 차단하거나 자료를 복구하지 않는다.
- 백업이 필요하면 *사용자가 별도 비공개 위치*(예: 로컬 암호화 디스크)에
  보관한다.
- 분실/훼손 시 책임은 사용자에게 있다. Boundary는 복구 절차를 제공하지
  않는다.

#### B2-3. 격리 폴더에서 Nextcore로의 지식 이전 절차 (OPEN_QUESTION 없이)

격리 폴더 → Nextcore 이전은 다음 *고정 절차*로만 진행한다. 절차 자체는
OPEN_QUESTION이 아니다 — *고정*이다. 적용 *대상*만 Inventory가 정한다.

1. *분석* — 격리 폴더의 자산을 읽고 동작을 이해한다 (역공학 허용).
2. *지식 단위 추출* — Design D8에 따라 "커널 인계 시 메모리 맵이 필요하다"
   같은 자연어 외부 요구만 추출한다. 비공개 필드 목록·자료구조·수치·오프셋은
   공개 이전 단위가 아니다.
3. *다른 표현으로 재박제* — 요구를 자연어로 재서술한다. 실제 구현은 별도로
   확인한 공개 인터페이스 근거와 합의된 설계에서 작성한다. 변수명·알고리즘
   표현을 바꾸더라도 격리 구현·레이아웃을 옮기는 것은 허용하지 않는다.
4. *근거 박제* — 이전된 *결정*만 `docs/NEXTCORE_DESIGN.md` 또는 본 문서에
   한 줄로 박제한다. "어떤 격리 자산에서 어떤 지식이 이전됐는지"가 *감사
   가능한 형태*로 남아야 한다.
5. *격리 자산 비포함 확인* — Nextcore 코드베이스가 격리 폴더를 *import*하지
   않음을 pre-commit 가드와 수동 점검으로 확인한다.

### B3. agent 과민 반응 금지

> *결정 근거: AGENTS.md §3(절대 금지)·§4(과민 반응 금지)와 일치. *공개 표준*
> 과 *공개 모듈*은 위험 신호가 아니다. 자료 이름·IPSW·NDA/EULA 언급만으로
> 작업을 중단하지 않는다. 확인된 공개 반입 위반에 한정해 해당 행위를 멈추고,
> 자산 분류 검토는 요청받은 구현·실행 검증과 병렬로 수행한다.*

다음 항목들은 agent가 보고 작업을 중단하지 않는다.

- macOS 부팅 도구라는 사실 자체.
- OpenCore의 이름을 언급하는 모든 행위 — OpenCore는 공개 부트로더다.
- Apple SMBIOS 모델명 (MacPro5,1 등).
- OpenCore kext 이름.
- `config.plist`, `boot-args`, DeviceProperties 키.
- macOS 버전 이름 (Tahoe, Sequoia 등).
- `createinstallmedia` 호출.
- EFI 관련 표준 (UEFI spec, ACPI spec, SMBIOS spec).
- 공개 DeviceTree 명세.
- SIP / SecureBoot / AMFI 등 Apple 보안 메커니즘의 우회 없이 동작하는 도구 (AGENTS.md §4 — 우회 없는 도구는 중단 사유 아님).
- OpenCore kext의 소스 코드 — 공개 출처를 읽고 인터페이스를 확인할 수 있다.
  라이선스는 각 모듈·파일 기준으로 기록하며 GPL로 일괄 단정하지 않는다.
- OpenCorePkg의 EFI 바이너리 — *공개 모듈*. 빌드 도구로 생성된 공개
  바이너리는 허용. *Apple 바이너리를 섞은 배포물*은 별도 (격리 검토).
- macOS IPSW·설치 매체·System 프레임워크의 언급 또는 사용자 보유 외부
  로컬 매체를 이용한 실행 시험. 원본·분석 결과·공개 산출물은 B7로 구분한다.
- Apple 공식 공개 XNU 저장소의 헤더·ABI·소스 열람. `PRIVATE` 같은
  전처리기 표시는 API 노출 범위를 나타낼 수 있으며 그 문자열만으로 자료의
  기밀 여부를 판정하지 않는다. 공식 공개 여부와 출처를 확인한다(B7).
- 위임된 범위의 격리 자료 로컬 열람·역공학. 그 결과를 공개 반입하는 행위는 별개다.

다음 항목들은 *해당 금지 행위만* 멈추고 근거를 보고한다. 독립 작업은 계속한다.

- 격리 폴더 자산을 공개 트리로 옮기는 시도.
- 사용자 시킨 적 없는 일을 단정적으로 진행하는 시도.
- force-push, 히스토리 재작성, 사용자 권한 없이 외부 변경 시도.
- 다른 에이전트의 슬롯을 직접 수정하는 시도.
- 확인된 비공개 자료를 허가 범위 밖으로 반입·공개하는 시도. 그 자료의
  반입을 보류하고 범위를 기록한다. 베타/NDA라는 단어만으로 판정하지 않는다.
- 사용자 시킨 작업을 *사이드트랙*으로 바꾸는 시도 — 보안 검토를 핍계로
  본 작업을 무기한 보류하는 행위 (AGENTS.md §3 명시).
- 사용자에게 *반복적으로* 확인 요청하며 작업을 무기한 보류하는 시도.
  OPEN_QUESTION은 한 번 박제되면 끝이어야 한다. 같은 항목으로 세션 동안
  세 번 이상 확인을 요청하면 *사이드트랙*이다.

### B4. 판단 요청 절차

> *결정 근거: AGENTS.md §2(미합의 항목은 OPEN_QUESTION으로 박제) 형식을
> 그대로 따른다. 형식 자체는 *고정*이며 슬롯별로 변형하지 않는다.*

agent가 *위 B3 항목 중 어디에도 속하지 않는* 상황에 직면하면,
추측하지 말고 OPEN_QUESTION으로 박제하고 다른 슬롯에 위임한다.

기록 형식 (고정):

```
OPEN_QUESTION: <slot>:<요지>
```

- `<slot>` — 위임 대상 슬롯 이름. `Inventory`, `Design`, `Build Plan`,
  `Prompts`, `Boundary`, `Ops` 중 하나.
- `<요지>` — 한 줄 요약. 미합의 항목의 *무엇*이 미합의인지 명시.

규칙:

- 한 항목 = 한 줄. 줄바꿈/코드블록/표 안에 묻지 않는다.
- 같은 요지로 두 슬롯에 동시에 박제하지 않는다 — *주 책임 슬롯* 한 곳에만.
- OPEN_QUESTION은 파일에 남긴다. 해당 슬롯을 위임받은 agent가 현재 세션에서
  근거를 확인했다면 같은 세션에 결정으로 해소할 수 있다. 세션을 넘기기 위한
  대기 절차가 아니다.
- Boundary 슬롯이 *자신의 결정으로* 해소할 수 있는 OPEN_QUESTION은
  박제된 결정으로 승격한다. 해소 불가능한 것은 그대로 둔다.
- 작성 형식 예시 한 줄: `OPEN_QUESTION: Design:공개 DeviceTree 명세의 범위 정의`.

### B5. 타 슬롯 OPEN_QUESTION 답변 (Boundary 관점 박제)

- (a) Design 질의 "어떤 자산이 격리 폴더에 들어가야 하는지" — 답변 박제: AGENTS.md §0 형체화에 해당하는 자산만 격리한다 (추출 blob·img4/인증서/키·IPSW 추출/BuildManifest·내부 동작 재구성 패닉 로그·내부 포맷 의존 분석물). 공개 스펙 문서·공개 크레이트·Nextcore 자체 산출물은 격리에 넣지 않는다 (B1 매트릭스 기준).
- (b) Build Plan 질의 "Mach-O / ACPI 명세 문서 허용 수준" — 답변 박제: 공개 명세 문서 범위까지만 공개 트리 허용 (Mach-O 공개 포맷 문서·ACPI 표준 테이블 정의·공개 크레이트 문서). Apple 비공개 확장·비공개 필드·내부 동작 역공학 메모는 격리로만 허용하며 공개 트리 코드는 내부 포맷에 의존하지 않는다.
- (c) Prompts 질의 "고급 토글 재노출 여부" — 답변 박제 (경계 관점): 고급 토글 재노출 자체는 경계 위반이 아니다. 공개 빌드/배포가 격리 자산·비공개 포맷·키/blob에 의존하도록 만드는 옵션은 금지한다. B7의 외부 로컬 실행 매체 선택은 그 반입과 구분한다. P5 제거 목록의 재노출 허용 여부는 Prompts·Design 판단에 위임한다.
- (d) Inventory 질의 "지금 도입해야 할 자산" — 당시 답변은 공개 구조 검증에 새 격리 자산이 필요하지 않다는 판단이었다. 2026-09-07 실제 macOS 실행 시험의 외부 로컬 매체는 B7 기준으로 사용할 수 있다. 원본을 공개 트리로 도입해야 한다는 의미는 아니다.
- (e) **RESOLVED-2026-09-07 — Design D10의 Linux backend 질의:** 공개 Linux 커널·DRM/KMS 드라이버는 Apple 격리 자산이 아니며, 사용자 요구에 따른 포팅/backend 후보로 분류한다. 설계 참고, 소스 포팅, 별도 실행 backend, firmware 파일을 서로 다른 도입 단위로 기록한다. 소스 도입 시 upstream URL·tag/commit·파일 목록·SPDX/라이선스·보존할 고지·패치 경로를 식별한다. 원문을 가져온 부분은 upstream 유래로 표시하고 클린룸 자체 구현으로 표기하지 않는다. 공개 커널 문서는 파일별 SPDX와 라이선스 표현을 사용하므로 일괄 라이선스 추정은 하지 않는다. DRM 계층은 메모리·IRQ·DMA 등도 담당하므로 UAPI 헤더만의 이식과 드라이버 backend 포팅은 별도다. 실제 링크·실행·배포 형태는 Build Plan이 결정하며, 그 형태가 정해진 뒤 필요한 고지·소스 제공 항목을 해당 upstream 조건에 대조한다. firmware/blob은 해당 파일의 별도 출처·조건을 확인하며 커널 소스 분류를 자동 적용하지 않는다. [Linux 라이선스 기록 규칙](https://docs.kernel.org/process/license-rules.html), [DRM 계층 문서](https://docs.kernel.org/gpu/introduction.html)

### B7. 공개 인터페이스 근거와 외부 로컬 실행 매체 (2026-09-07)

(결정: Boundary 슬롯 확정 — 자료의 저장·출처 분류이며 실행 성공 또는 법적 판단이 아니다.)

#### B7-1. 공식 공개 XNU 헤더·ABI

- **커널/부트 ABI 자료 계층:** Apple이 공식 공개한
  [XNU 저장소](https://github.com/apple-oss-distributions/xnu)와
  [i386 부트 헤더](https://github.com/apple-oss-distributions/xnu/blob/main/pexpert/pexpert/i386/boot.h)는
  출처가 공개된 기술 자료다. Apple 이름·커널 내부 경로·`PRIVATE` 표기만으로
  유출/NDA/격리 자산으로 분류하지 않는다.
- 공개 소스에서 확인된 인터페이스의 설명·형식 요구는 공개 설계 근거로
  사용할 수 있다. 이 근거에 따른 독립 호환 구현은 격리 역공학 결과를 옮기는
  것과 구분한다. 인용할 때 upstream tag/commit, 파일, 아키텍처, 적용하려는
  게스트 빌드를 기록한다. 본 절은 헤더 또는 Apple 구현 코드의 원문을
  Nextcore로 복사하는 승인이 아니다. [XNU 배포 라이선스 원문](https://github.com/apple-oss-distributions/xnu/blob/main/APPLE_LICENSE)
- **공개성과 지원 안정성은 별도:** 공개된 필드·기호라는 사실이 안정적
  외부 API, 특정 macOS 빌드와 동일한 ABI, 직접 XNU 부팅 가능성을 증명하지
  않는다. 공개 릴리스와 실제 게스트가 다르면 그 차이를 미검증으로 기록한다.
- 격리 분석에서 얻은 코드·내부 레이아웃·상수·오프셋은 계속 공개 이전 금지다.
  공개 근거를 확보했다고 격리 코드를 재명명해 옮길 수는 없다. D5/D7의 설계
  범위를 바꿀 필요가 있으면 Design→Build Plan 순서로 위임한다.

#### B7-2. macOS 설치·복구·게스트 디스크의 실행 사용

- **실행 매체 계층:** 사용자가 보유한 원본 IPSW, 설치 이미지, 복구 매체,
  기존 게스트 디스크를 외부 로컬 경로에서 QEMU/Virtualization.framework
  시험의 입력으로 사용할 수 있다. macOS 실행 검증 요청에 포함되는 범위이며
  파일명·EULA·베타 표기만으로 재확인하거나 전체 작업을 중단하지 않는다.
- 원본 매체는 보존한다. 쓰기 가능한 VM 디스크가 필요하면 별도 작업 디스크나
  overlay를 사용한다. 매체 본체·추출 blob·framework·캐시·인증 자료는 공개
  소스, Cargo 빌드 입력, 배포 archive, CI fixture로 포함하지 않는다.
- **분석 결과 계층:** 추출·역공학 산출물은 `_isolated/`에 두며 어떤 staged
  영역에도 넣지 않는다. 외부 원본 경로를 실제 실행 시 명시적으로 전달하는
  것은 공개 코드가 `_isolated/`를 import/include하거나 공개 빌드가 그 자료에
  의존하는 것과 다르다.
- **공개 검증 기록 계층:** 매체 종류·공개 빌드 식별자·아키텍처, 시험 명령,
  종료 상태와 관찰한 부팅 단계를 기록한다. 키·원문 dump·복구 이미지·개인
  식별 데이터·내부 구현 재구성 내용은 공개 증거로 복사하지 않는다. 로그가
  혼합 자료라면 원본은 격리하고 필요한 결과만 재서술한다.
- **공식 도구 근거:** Apple은 Virtualization.framework를 사용하는 macOS VM
  설치/실행 흐름과 restore image 사용을 공개 문서로 제공한다. 이는 공개
  API와 매체 사용 흐름의 근거이며 모든 호스트·배포 방식의 법적 판정이나
  Nextcore 구현 완료의 근거로 확대하지 않는다. [Apple macOS VM 예제](https://developer.apple.com/documentation/virtualization/running-macos-in-a-virtual-machine-on-apple-silicon)

#### B7-3. 병렬 진행 원칙

Boundary 검토는 root/APLS의 실제 실행 작업과 병렬이다. 자료 분류가 미정이면
그 자료의 공개 반입만 보류하고 공개 ABI 검토·host 테스트·EFI 실행·독립
backend 구현은 계속한다. 확인된 금지 행위는 B3 범위에서만 중단한다.

## 결정 근거 메모 (B1~B4)

- B1 — AGENTS.md §0(형체화 금지)·§4(과민 반응 금지)에 따라 *공개 표준*
  및 공식 공개 인터페이스는 출처 근거로 사용한다. 비공개 분석물·추출 blob은
  공개 트리로 옮기지 않는다. 법적 적용 여부는 자료 이름으로 단정하지 않으며,
  외부 원본 매체의 로컬 실행은 B7에서 별도로 다룬다.
- B2 — 격리 폴더는 *참고용*이며 운영 책임은 사용자다. 코드는 격리 폴더를
  *import하지 않는다* (AGENTS.md §5). 지식 이전은 *다른 표현으로의 재박제*
  만 허용한다 (AGENTS.md §0). 백업은 *사용자 책임*임을 명시해 Boundary의
  책임 범위를 닫는다.
- B3 — 공개 모듈·공개 XNU 헤더·IPSW 언급·위임된 격리 열람은 전체 작업
  중단 사유가 아니다. 공개 반입 등 확인된 금지 행위만 멈추고, 실행 검증과
  분류 검토를 병렬로 진행한다 (AGENTS.md §0/§3/§4).
- B4 — OPEN_QUESTION 형식 `OPEN_QUESTION: <slot>:<요지>`는 AGENTS.md §2의
  *고정 형식*이다. Boundary가 자신의 결정으로 해소 가능한 항목만 승격하고,
  다른 슬롯 판단이 필요한 것은 그대로 둔다.
