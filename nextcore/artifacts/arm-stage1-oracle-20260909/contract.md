# BP32 operation-level actual Arm abort oracle

Read-only CPU integration review and standalone authored oracle, owned outside all repositories. The BP29 actual EL1-abort framework is preserved and hashed; adapted assembly/C/Python files are authored only in this directory. No original Apple input or trace is read. No production source, metadata, pin or prior receipt is changed.

Scope: AArch64 EL1 (and EL0 where setup permits), stage1 with 4 KiB or 16 KiB granules, MAIR Attr0=0x44 Normal-NC, noncacheable nonshareable walks, ASID0, HCR_EL2.RW=1 and VM=0, SCTLR_EL1=0x30d00803 (M=1/A=1, little endian). Compare actual load/store and 32/64-bit integer pair accesses against invalid translation, AF=0 and AP denial. Pair second-page cases cross adjacent VA pages with discontiguous physical backing. Fetch cases include invalid/AF/PXN or UXN denial and misaligned-PC priority. Capture actual ESR/FAR/ELR, control snapshots and all descriptor inputs.

Expected architectural results are defined independently of Nextcore implementation. Alignment with SCTLR.A=1 is expected before stage1 translation; this expectation remains provisional until primary architecture support and actual execution agree. QEMU is an implementation oracle, not architectural authority; unsupported QEMU behavior must be recorded without changing production semantics to match it. The verifier checks EC/IL/FSC/WnR/FAR/ELR and control regime, requires expected exception presence, and includes an actually compiled negative variant that changes a control or descriptor to violate one expected result.

The source and framework hashes must be unchanged after execution. All subprocesses are bounded, no hardware/EFI/native JIT/macOS/Metal success is implied. Results are sent to CPU/root before any integration decision.

## Confirmed source and final execution scope

The original Arm DDI0487B.a manual was obtained from the public university mirror https://cs140e.sergio.bz/docs/ARMv8-Reference-Manual.pdf (SHA-256 24ebe2e085a4f9e6588ac8118e2b8747baec35184c44211e01751eb176c1d76e). It is Arm-authored documentation hosted by a third party, not a claim of a current official Arm URL. D1.13.3, page D1-1827 gives PC alignment priority over instruction abort. D4.7.3, pages D4-2110/2111 gives non-memory-type alignment priority over translation/AF/permission. Table D4-34, pages D4-2077/2078 makes EL0 execution independent of AP data permissions and makes EL0-writable memory non-executable at privileged level. The first scope needs no later optional extension to implement these baseline rules. Arm staff also confirm the latter distinction at https://community.arm.com/forums/f/architectures-and-processors-forum/53584/cortex-a-permission-fault-due-to-code-region-mapped-as-read-write/178834, with DDI0487I.a statement references WXKKQ/LJHZZ.

Final default suite runs 428 cases and an actually compiled A=0 negative variant. A separate opt-in run includes 12 known QEMU PC-alignment-priority contradictions; the strict architecture verdict and CLI remain failed for that run. They must not be turned into architecture passes or used to change production PC-first behavior. AP execution expectations were corrected from the independent Arm table before the final executions. Actual TTBR/TCR/SCTLR/MAIR and saved SPSR mode/PAN/UAO/DAIF plus handler EL are checked. The initial trial with an EL0-writable handler identity mapping faulted before the authored target; it was rejected, then corrected to a read-only handler/code mapping. It is not a production result.
