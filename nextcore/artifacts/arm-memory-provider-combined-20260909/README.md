Default generic EFI, direct trace, provider-only, provider+tiered, and UEFI --all-features all build; the latter produces all ten eligible x86 UEFI binaries. Full source and dependency identities are preserved in metadata.json, build-results.json and canonical-dependency-sources.json. Cargo's untracked .cargo-ok cache marker is recorded separately from unchanged tracked source.

The canonical combined binary (SHA256 4c4371e0e69e0e4d0374dd69ddf9d63b26ddfa01656c6aea25ff78b49c474c12) passes all 23 authored provider cases: 11 scalar, 6 pair and 6 range/PC boundaries. A separately cloned failure-injection variant uses one explicit auxiliary-package path patch to return -7 before data transfer. It passes the callback-failure case without inventing a guest ESR/FAR or completed data operation. This variant is not included in the canonical production dependency claim. The canonical direct binary computes the correct signed byte fixture while the provider verifier rejects the actual bypass with exit 1.

All receipts, 27 original authored serial logs, frozen provider/tiered helpers, commands and the standalone Cargo.lock are included. No original OS image, EFI binary, firmware or ESP is published here. Historical provider-only evidence is unchanged and distinct from this integrated source/binary.

To repeat the canonical build, use an independent checkout at the recorded EFI revision and the recorded Cargo.lock. With Rust 1.98.1 and x86_64-unknown-uefi installed, run cargo metadata --all-features --filter-platform x86_64-unknown-uefi --format-version 1 using a fresh CARGO_HOME, then the exact locked build commands in build-results.json. Each canonical dependency source must match metadata.json. Reuse helpers/provider/reproduce.py with the separately saved combined/direct/transport binaries and frozen host tools; its command record is in provider-replay.json. Use helpers/tiered/verify_tiered_budget_ovmf.py with the frozen tier-aware trace host tool for the 256 test. The transport mutation and explicit patch scope are in transport-variant.json.

This validates M=0 authored execution with Boot Services active. M=1, post-fault RAM observation, physical-machine execution, macOS boot and guest Metal remain unverified. No source, pins, commits or historical artifacts were changed by this verification.
