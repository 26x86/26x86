# BP34 independent one-way stage-1 enable oracle

Current: the BP32 independent oracle exercises immutable M=1 mappings. Root delegates an independent authored actual Arm M=0 to M=1 transition proof for the new CPU profile; no production/root edits are permitted. CPU confirmed the following scope.

Use a freestanding AArch64 ELF under QEMU virt/max with explicit HCR.RW=1 and no stage2. Enter EL1h through ERET with I/F/DAIF masked, SCTLR.M=0/A=1/C=I=0, MAIR0x44, aligned independent TTBR roots, fixed 4K/T0SZ=T1SZ16 or 16K/T0SZ=T1SZ17 Normal-NC translation controls. The latter begins at level1; a 48-bit 16K regime would instead require level0. At the end of an identity-mapped granule, execute MSR SCTLR_EL1 at offset granule-8 and exact ISB SY at granule-4. Both instruction spans are safe before and after enable. Immediately following fetch crosses to a different mapped physical page; target code captures post-ISB SCTLR/PC and loads/stores through a nonidentity data VA. Actual DSB SY/TLBI VMALLE1/DSB SY/ISB and reread may be exercised, but immutable mappings provide no observable hardware refill count.

Two granules each cover success, missing post-ISB code page, and missing data page. Actual ESR/FAR/ELR and pre/post controls are read from architectural registers. Capture table addresses and every nonzero descriptor in explicitly zeroed allocated table pages, original payload instruction bytes and physical data before/after. Successful fetch PC, initial loaded value, stored readback and physical effects establish nonidentity behavior. Expectations are architectural/public-contract authored, never derived from the JIT implementation.

Build two separate negative ELFs, changing only positive cases: replace the actual enable MSR with NOP (physical next page contains a distinct terminating decoy), or omit the next-page mapping. Each must finish normally while the ordinary positive comparator rejects exactly those two cases, with the intended final-M/decoy or instruction-translation syndrome. Missing markers, crashes, unrelated failed cases or arbitrary nonzero exit are not detection.

No claim is made about deterministic pre-ISB visibility. Hardware may apply controls early; the common mapping ensures safety either way. No immutable-table readback is presented as evidence of actual TLB eviction/refill, and service reader counters are separate. This is one independent software CPU, not physical hardware, generated x86, EFI, normal macOS or Metal.
